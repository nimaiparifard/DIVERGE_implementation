2. PROBLEM B - MULTIPLE-COMPARISON CORRECTION
---------------------------------------------------------------------

Four tests at alpha = 0.05 -> family-wise error rate up to 1-0.95^4 = 18.5%.
The reviewer's arithmetic is correct: Bonferroni threshold 0.05/4 = 0.0125,
WikiCS p = 0.0181 > 0.0125 -> WikiCS is NOT significant under Bonferroni
(Bonferroni-adjusted p = 4 x 0.0181 = 0.0724).

The right fix: Holm-Bonferroni (Holm 1979).
  - It controls exactly the same family-wise error rate as Bonferroni,
    under exactly the same (no) assumptions.
  - It is uniformly more powerful: it never rejects less than Bonferroni.
  - It is already the correction used in exp4_stability_significance.py
    (holm() function), so the paper becomes consistent.

Holm procedure: sort p ascending, compare the k-th smallest with
alpha/(m-k+1), stop at the first failure.

  rank  dataset   p (corrected chi2)   Holm threshold   Holm-adjusted p   reject?
  1     PubMed    4.59e-38             0.05/4=0.0125    1.84e-37          yes
  2     Cora      1.92e-9              0.05/3=0.0167    5.76e-9           yes
  3     CiteSeer  9.73e-5              0.05/2=0.025     1.95e-4           yes
  4     WikiCS    0.0181               0.05/1=0.05      0.0181            yes

-> All four survive Holm. With 5 datasets (after adding ArXiv, Section 3)
   WikiCS is still fine as long as ArXiv's p is below 0.0181 (then WikiCS is
   compared with 0.05) or at worst compared with 0.025 (0.0181 < 0.025).
   Benjamini-Hochberg FDR also rejects all four (WikiCS BH-adjusted p =
   0.0181).

HOW TO PRESENT IT HONESTLY (important):
Switching from Bonferroni to Holm AFTER seeing that Bonferroni fails can
look like method shopping to the reviewer. Defuse this explicitly:
  (1) Report BOTH the Bonferroni-adjusted and Holm-adjusted p in Table 9.
  (2) Say openly that WikiCS does not survive the plain Bonferroni bound,
      that it survives Holm, which controls the same error rate, and that
      the WikiCS effect is small (+1.37 pp, see effect sizes below).
  (3) Justify Holm by its properties (same FWER, uniformly more powerful)
      and by consistency with the other tests in the paper - not by the
      fact that it makes WikiCS significant.
  (4) Soften the WikiCS conclusion in the text ("weaker evidence").

Also add EFFECT SIZES. A p-value alone says nothing about how large the
gain is. For McNemar the natural ones are:
  - accuracy difference (c - b)/n with a 95% CI
  - discordant odds ratio c/b

  Dataset    n      acc. diff (c-b)/n     c/b
  Cora       542    +9.78 pp              5.82
  PubMed     3944   +5.76 pp              6.68
  CiteSeer   638    +4.39 pp              3.80
  WikiCS     2341   +1.37 pp              1.46

Do NOT switch to a one-sided test to halve the WikiCS p-value; H1 in the
paper is two-sided and changing it after the fact is exactly what the
reviewer is watching for.

4. PROBLEM D - TEST DIVERGE AGAINST BASELINES
---------------------------------------------------------------------

This is the most important part. Table 9 tests "fine-tuned single view vs
base embeddings". It says nothing about "DIVERGE vs TAPE / ENGINE /
LLaGA ...", which is the claim in the abstract and in Tables 5-6.

The obstacle: the baseline numbers are copied from Wu et al. (2025). You do
not have their per-node predictions, so McNemar (a paired, per-node test)
is impossible against them. Split the problem in two:

4.1  Paired per-node tests (McNemar) against IN-HOUSE comparators
     Everything you train yourself on the same split has per-node
     predictions. For each dataset test DIVERGE (the final ensemble,
     e.g. Method 3) against:
       (a) base LLaMA-3.2-1B embeddings + GraphSAGE    (no fine-tuning)
       (b) best single LoRA view + GraphSAGE          (no ensemble)
       (c) uniform average of the 5 views             (no learned head)
       (d) seed-only ensemble (5 x Gaussian, diff. seeds) - if already run
           for R2-C2 / R4-C1
       (e) TAPE re-run in-house (repo already has TAPE/ ; R4-C2 asks for
           this anyway) and STAGE/UltraTAG if re-run (R4-C4)
     This directly answers "is the gain from fine-tuning, from diversity,
     from the head, or from the method as a whole?" and makes Table 9 a
     real ablation-significance table instead of a single side claim.
     Family: 5 comparators x 5 datasets = 25 tests -> Holm over all 25
     (or Holm per dataset, but say which).

4.2  Unpaired tests against BORROWED baselines (Wu et al.)
     Wu et al. report mean +/- std over several runs. Run DIVERGE with
     several seeds (at least 5; ideally different split seeds, since the
     reviewer also asks for mean +/- std in R4-C2) and use Welch's t-test
     from summary statistics:
         scipy.stats.ttest_ind_from_stats(m1, s1, n1, m2, s2, n2,
                                          equal_var=False)
     Compare DIVERGE with the strongest baseline per dataset (TAPE, and
     LLaGA on ArXiv), Holm over the 5 datasets.
     State the caveat clearly: this test compares the numbers as reported;
     it cannot remove differences in split, hardware or tuning between the
     two sources (which is also the reason for re-running TAPE in 4.1).

     NOTE: Tables 5-6 currently show "+/-0.00" for every row. That is a
     placeholder and must be filled with real std values (or removed) -
     a reviewer will read +/-0.00 as "single run".

4.3  (Optional) across datasets: Friedman test + critical-difference
     diagram (Demsar 2006). With only 5 datasets the power is low
     (a Wilcoxon signed-rank test over 5 datasets cannot go below
     p = 0.0625 two-sided), so use it only as supporting evidence, never
     as the main test.

7.1 Replace the equation and the paragraph after it:

\revfour{The McNemar statistic with Edwards' continuity correction is
\begin{equation}
\chi^2 = \frac{\left(|b - c| - 1\right)^2}{b + c},
\label{eq:mcnemar}
\end{equation}
which follows a $\chi^2$ distribution with one degree of freedom under
$H_0$. When $b+c<25$ the exact binomial form of the test is used instead.
Because the same hypothesis is tested on several datasets, the $p$-values
are adjusted with the Holm--Bonferroni procedure \citep{holm1979simple},
which controls the family-wise error rate at $\alpha=0.05$ and is uniformly
more powerful than the Bonferroni correction. For transparency we also
report the Bonferroni-adjusted $p$-values and, as effect sizes, the
accuracy difference $(c-b)/n$ and the discordant odds ratio $c/b$.}

Response:

We thank the reviewer for the careful reading of our statistical analysis;
all four points were correct and have been addressed.

(1) Formula. The values in Table 9 were computed with Edwards' continuity-
corrected McNemar statistic, whereas Eq. (36) showed the uncorrected form.
We have corrected Eq. (36) to $\chi^2=(|b-c|-1)^2/(b+c)$, which reproduces
all values in the table, and we now state that the exact binomial version
is used when $b+c<25$.

(2) Multiple comparisons. We agree that a correction is needed. We now
adjust all $p$-values with the Holm--Bonferroni procedure, which controls
the family-wise error rate at the same level as the Bonferroni correction
and is uniformly more powerful; the same procedure is used for all other
tests in the paper. Table 9 now reports both Bonferroni- and Holm-adjusted
$p$-values together with effect sizes. As the reviewer notes, the WikiCS
result ($p=0.0181$) does not pass the plain Bonferroni bound; it does pass
Holm. We now describe the WikiCS evidence as weaker and note that its gain
is small ($+1.37$ pp), while the effects on the other datasets are large
($+4.4$ to $+9.8$ pp) and remain significant under either correction.

(3) OGBN-ArXiv. [Its base-model embeddings had not been extracted at the
time of submission.] We have now run the test on OGBN-ArXiv
([n] test nodes, $b=\dots$, $c=\dots$, Holm-adjusted $p=\dots$), and Table 9
covers all five datasets.

(4) Tests against baselines. We agree that the fine-tuned-vs-base test does
not test the main claim. We added a new analysis (Section X, Table Y):
(a) paired McNemar tests on identical test nodes between DIVERGE and every
