1. THE SIMPLE IDEA BEHIND ALL EXPERIMENTS
---------------------------------------------------------------------

  The pool: every init (PiSSA, Orthogonal, Gaussian, LoftQ, EVA) is
  fine-tuned 4 times with 4 LoRA seeds (42-45) -> 5 x 4 = 20 models.
  (Cora + LLaMA: 16 models, Orthogonal seed caches are missing.)
  On each model we train one GNN with the SAME GNN seed. So two models
  can differ only in their init, only in their seed, or in both.

  For every pair of models we measure "how different are they" at one
  stage of the pipeline, and put the pair in one of three groups:

    seed-only : same init, different seed   = pure training randomness
    init-only : different init, same seed   = pure init effect
    both      : different init and seed

  Then we ask two questions at every stage:

    Q1 (weak)   Does the init ADD diversity on top of the seed?
                Test: "both" pairs vs "seed-only" pairs, permutation
                test (2000 shuffles). Significant = p < 0.05.
    Q2 (strong) Does the init change things MORE than the seed?
                Ratio = init-only / seed-only. Ratio > 1 = yes.
                Test: one-sided Mann-Whitney. Significant = p < 0.05.

  And one link question between neighbouring stages:

    LINK  Are pairs that are far apart in stage k also far apart in
          stage k+1? Test: Mantel test (Spearman rho, permutations).

  Q1 answers "init is not zero / not only noise".
  Q2 answers "init is a bigger source of diversity than the seed".
  LINK answers "the init effect travels down the pipeline".

  Rule used below: a stage PASSES on a dataset if the test is significant
  for at least 2 of the 3 LLMs (CiteSeer + LLaMA is not counted, so on
  CiteSeer it means both Gemma and SmolLM).

2. STAGE 1 - ADAPTER WEIGHTS
---------------------------------------------------------------------

  What we did (simple)
    Each LoRA layer only changes the model inside a small 8-dimensional
    "window" (the row space of A = where it reads, the column space of B =
    where it writes). For two models we check how much their windows
    overlap, averaged over all LoRA layers. 1 - overlap = distance.
    0 = same window, 1 = completely different window.
    Extra: we check WHERE each window sits in the pretrained weight W:
    on its strongest directions (top singular vectors) or its weakest.

  Results (distance of the trained update B*A)
                       seed-only  init-only  ratio   Q2 p     Q1 p
    Cora     Gemma       0.64      1.00      1.57x   0.004    <0.001
    Cora     LLaMA       0.53      1.00      1.89x   0.002    <0.001
    Cora     SmolLM      0.60      1.00      1.66x   <0.001   <0.001
    CiteSeer Gemma       0.64      1.00      1.56x   0.006    <0.001
    CiteSeer LLaMA (!)   0.62      1.00      1.61x   0.017    <0.001
    CiteSeer SmolLM      0.60      1.00      1.66x   <0.001   <0.001
    (row(A) and col(B) give the same picture: ratio 1.55-1.96x, all p<0.02)

  Seed-only distance per init (same for both datasets):
    PiSSA 0.01-0.06, LoftQ 0.03-0.14  -> the seed almost does not move them

    - for Gaussian / Orthogonal / EVA: a NEW random A matrix, i.e. a new
      init (seed-only adapter distance 0.96-1.00, as big as init-only)
    - NOT the data order and dropout (HF Trainer seed was always 42)
  So "seed-only" is partly an init change plus a split change. Comparing
  init-only against it is unfair, and Q2 cannot be answered with it.

10.2 The one experiment
  ONE pool design, measured at all 4 stages with the same members (no

      - LoRA A/B draw      = draw 0     (--init_seed 0)

    seed-only pair = SAME init, SAME starting adapter, different random

10.4 Why this can pass Q2 now

10.5 MUST FIX BEFORE RUNNING: "EVA" is not EVA in train_llm/
  train_llm/peft_model.py:get_lora_model passes init_lora_weights="eva" to
  PEFT, but never calls peft.initialize_lora_eva_weights(model, loader).
  In PEFT, "eva" without that call only sets B = 0; A keeps the default
  random (Kaiming-uniform) init of the Linear layer. So every "EVA" member
  in the diversity pools (and the main DIVERGE runs that use train_llm/)
  is a plain random-A LoRA, close to Gaussian. This explains why EVA

  (EvaConfig + initialize_lora_eva_weights).

    - The paper's Mechanism paragraph says EVA uses "the principal

       the pool with and without it (--exclude_collapsed).

E1. MAIN EXPERIMENT: CONTROLLED POOLS (answers Q2 at all 4 stages)
---------------------------------------------------------------------
  Pools (fixed now, never changed after seeing results):
    5 datasets x 2 LLMs = 10 pools
    datasets: cora, citeseer, pubmed, wikics, instagram
    LLMs:     gemma2_2B, llama_3.2_1B

  Members per pool: 5 inits x 5 training seeds (42-46) = 25
    (5 seeds instead of 4, so the SAME models also give 5-member
     single-init ensembles for E3; costs 50 extra fine-tunes in total)
    for every member: --split 1 --split_seed 42 --init_seed 0
    GNN: same split 42, same GNN seed, same hyperparameters.

  What is measured (one distance per stage, fixed now):
    1 adapter weights   1 - cos(BA)
    2 LLM embeddings    1 - CKA
    3 GNN embeddings    1 - CKA
    4 GNN predictions   disagreement on test nodes
    secondary: 10-NN neighbourhood distance on LLM and GNN embeddings

  Test in one pool (init_vs_training_noise.py):
    ratio = mean(init-only) / mean(seed-only)
    crossed bootstrap over inits and seeds -> 95% CI, p(ratio <= 1)

  Claim over the 10 pools (aggregate_q2.py), per stage:
    CLAIM "init > seed" only if
      sign test: >= 9 of 10 pools have ratio > 1   (p = 0.011)  AND
      one-sided Wilcoxon on log(ratio)             p < 0.05
    Report all 10 pools in the appendix, also the ones that fail.

  Commands: scripts/run_q2_experiment.bat
    (change TRAIN_SEEDS to 42 43 44 45 46, and --seeds 42,43,44,45,46)

  Cost: 10 x 25 = 250 fine-tunes + caching.
    Cheaper fallback if the GPU budget is too small: run cora + citeseer
    first (4 pools, 100 fine-tunes). If all 4 pass a stage, add the other
    6 pools. If 2 or more of the 4 fail a stage, that stage cannot reach
    9/10 any more; stop and write it as a limitation.

E2. RANDOM-DRAW ARM (answers meaning (ii), optional but recommended)
---------------------------------------------------------------------
  Question: is a different init STRATEGY a bigger change than a new
  random draw of the SAME random strategy?

  Extra members, only for the random inits (Gaussian, Orthogonal, and
  EVA if it stays random), at training seed 42:
    --init_seed 1, 2, 3   -> 3 inits x 3 draws = 9 extra fine-tunes/pool
  Run on 4 pools (cora, citeseer x 2 LLMs) = 36 fine-tunes.

  Pairs (all with training seed 42):
    draw-only     : same random strategy, different init_seed
    strategy-only : different strategy, same init_seed (from E1)
  Ratio = strategy-only / draw-only, same bootstrap, same 4 stages.
  Report it separately for
    - deterministic vs random  (PiSSA/LoftQ vs Gaussian/Orthogonal)
    - random vs random         (Gaussian vs Orthogonal vs EVA)

  Expected honest result: "random vs random" ~ 1 (two random strategies
  are like two random draws), "deterministic vs random" > 1. Then the
  paper says: the strategies that choose WHERE to adapt (PiSSA, LoftQ,
  real EVA) give diversity that a new random seed cannot give; the random
  strategies are one family. That is a real, defensible answer.

  Needs: init_vs_training_noise.py to accept extra (init, init_seed)
  members and a "draw-only" pair group (not written yet).

E3. ENSEMBLE ARM (answers R3-C2 directly; no extra fine-tunes)
---------------------------------------------------------------------
  Uses the E1 models of each pool (all on split 42, 5 x 5 grid).

    multi-init ensemble  : the 5 inits at one training seed t
                           -> 5 ensembles (t = 42..46)
    single-init ensemble : one init with its 5 training seeds
                           -> 5 ensembles (one per init)
  Same size (5 members), same GNNs, same heads: uniform + DIVERGE
  Methods 1-3, configuration and epoch selected on VALIDATION.

  Per pool: diff = mean acc(multi-init) - mean acc(single-init).
    Also report the best single-init ensemble (the strongest "seed
    ensemble" a practitioner could pick) as a harder baseline.
  Over 10 pools: same rule as E1 (>= 9/10 positive + Wilcoxon p < 0.05),
  primary head = Method 2 (named now).
